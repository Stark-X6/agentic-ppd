# 阶段 5：PPD/AMPD 假设验证与改进空间实验设计

日期：2026-10-27。状态：实验设计草案，尚未启动 GPU 实验；不是新算法已经有效的结论，也不是完整 calibration 的执行清单。

本轮研究顺序改为：**先证明现有信息会造成有代价的错选，再决定需要哪些状态和算法。** 过去讨论的高维查表、窗口积压、拥塞修正、AMPD-inspired 门控与 route-aware TTL 都保留为候选，不能先实现一种方案，再只寻找支持它的数据。

关联文档：[handoff](./agent-to-ppd-handoff.md)、[历史实验](./agent-ppd-experiment-log.md)、[变量与路由理论](./stage5-state-aware-routing-and-ttl-design.md)、[早期问题清单](./stage5-agent-compatible-dynamic-theory.md)。输入和计时边界继续遵守 [状态语义契约](/root/vllm-ppd/docs/stage5_state_semantics_contract.md)，实现能力以 [只读观测说明](/root/vllm-ppd/docs/stage5_readonly_observer.md) 为准。

## 1. 本轮要回答什么

本轮不以增加 Remote 比例、提高 P 利用率或得到一张更复杂的表为目标，而要回答三个依次成立的问题：

1. **存在性：**固定当前数据面和 P:D，是否存在有代表性的状态，使 Local/Remote 的优劣发生可靠变化？
2. **重要性：**这些状态在真实 Agent 中多常见，选错会多花多少时间、造成多少停顿或失败？
3. **可利用性：**决策前能否以足够低的开销观测到区分这些状态的信息，并在独立测试中改善选路？

只有第三项也成立，才有理由投入新的路由系统。TTL 还要另证：可避免的容量失效是否足够多，以及保护缓存的收益能否超过它给其他请求带来的代价。

本文给出可证伪的假设、受控实验和分阶段预算。数值档位是候选测试水平，不是当前硬件已经能实现的状态；正式启动前需通过 E0 并冻结运行清单。

### 2.2 对两篇论文的准确表述

**PPD 的待验证局限：**原特征不能显式区分节点的实际可复用前缀和当前执行背景；当前 Agent 接口还存在 output cap 与未来实际输出不等价、到达率口径不同、长 context 超出旧校准域等问题。它的优势是直接测量复杂执行的综合结果，不要求精确分解全部干扰；这些结果是否适合当前状态则需要验证。[PPD §3/5/7](https://arxiv.org/html/2603.13358v2)

**AMPD 的待验证局限：**它考虑了队列和窗口 ITL/TTFT，并利用 D 保存的历史 KV，不能概括为“不考虑负载、不复用 KV”。其路由公式没有显式区分我们关注的两端实际 C_P/C_D；队列成本采用逐任务 prefill 估计求和，是否适合当前分块/合批执行尚未知。v2 将 chunked prefill 列为未来工作。论文的整体 SLO 改善不是逐请求等待估计准确性的直接证据。[AMPD §3、§4、§8](https://arxiv.org/html/2602.14516v2)

本项目采用固定 P/D affinity 和单向 P→D connector；没有复现 AMPD 的双向历史 KV 读取和完整执行系统。任何移植比较必须称为 **AMPD-inspired on PPD**，不能把本机简化实现的不足写成已证实的 AMPD 原系统缺陷。

## 3. 可证伪的假设清单

| 编号 | 尚待验证的猜想 | 什么结果支持它 | 什么结果会削弱或否定它 | 对应实验 |
|---|---|---|---|---|
| H0：存在值得利用的路由空间 | 常见 Agent 状态中，最佳路径不是总为 Local；状态化选择能比最好的固定路径更好 | 两种路径各有稳定优势区，真实分布加权后仍有可观收益 | 仅极罕见人造状态偏好 Remote，或收益小于观测开销/噪声 | E1–E3、E6 |
| H1：实际 KV 前缀是关键缺项 | 同样 N/H/A，C_P/C_D 的变化会改变路径收益；逻辑短 append 不保证本地计算少 | 固定 prompt 和背景，改变缓存后产生可重复的代价变化或胜负反转；加入 C/U 降低留出集错选 | 复用变化只改变绝对延迟，不影响路径相对优劣；或相关状态极少 | E1 |
| H2：结构化 decode 状态有增量信息 | B_D/K_D 能区分相同 QPS 或相近近期 ITL 下的 Local 干扰 | 在相同请求/缓存下，改变 decode 背景导致动作或代价变化；B/K 比仅窗口 ITL 有稳定的额外价值 | 仅 ITL 已足够，或 B/K 的改善小于成本；相同 B/K 内差异仍很大 | E2、E6 |
| H3：积压不可完全省略，但可低维描述 | P/D prefill 积压会改变路由；每节点窗口平均剩余 tokens 可能足以替代高维积压表 | 同请求/缓存/decode 背景下积压改变胜负；低维指标在留出突发/排空轨迹上仍能减少错选 | 仅在训练数据有效；窗口滞后；相同统计量下稳定反转，必须补更多信息 | E3 |
| H4：原特征与 Agent 工作不匹配 | output cap、旧短 context、append bypass 不能稳定表征实际工作；长 tool observation 和长 reasoning 都可能重要 | token 对齐后发现明显代理误差，且受控测量表明它导致有代价的路径错误 | 只有数值误差、没有动作或性能差异；新输入无增量收益 | CPU 审计、E1、E4 |
| H5：候选请求评分可能漏掉系统代价 | 候选 TPOT 不一定记录 prefill 期间对其他 decode 的停顿；原 score 改善也未必缩短完整响应/episode | 候选指标与背景停顿或固定轨迹完成时间出现可重复冲突 | 指标在研究域内一致，没必要先引入新 SLO 惩罚 | E2、E3、E6 |
| H6：TTL 与路由可能互补，也可能冲突 | 部分工具间隔中的容量驱逐可避免；保护正确节点的前缀能改善后续路径，但 pin 可能放大拥塞 | 有已证实的容量失效与后续重算；等容量 TTL 对照净收益为正，且路由×TTL 存在有益交互 | loss 主要来自模板分叉；容量本已不足；保护减少 miss 却增加等待/失败 | E5，后置 |

“output 不可预测”在本文中收紧为“当前没有经验证的、适合本任务的可靠预测器，主方案不依赖未来 G”，不宣称数学上不可能预测。窗口积压、惩罚函数和 TTL 都是待比较的方法，不是上述假设的同义词。

## 4. 固定条件、硬件与数据

### 4.1 代码与 Agent 基线

设计时的代码锚点：vllm-ppd `c0b7a0aec5b3bbcf0523cae6e92d4af0f41513dc`，uni-agent `449f80f4383b1acf446bf5b7a6e2afce56093813`。每次运行另记实际 commit、dirty diff 和配置哈希，不移动旧 baseline tag。

除被明确操纵的实验因素外，保持：

- Qwen3-30B-A3B-Thinking-2507、BF16、同一 tokenizer/chat template；
- Agent context 155648、episode completion budget 131072、per-turn cap 16384、temperature=0、reasoning replay 和现有工具 schema；
- 4 张 GPU、2P:2D、固定候选 P/D、不迁移 D、不引入 D→P 传输；

受控微基准可以设置不同的候选生成长度以隔离计算工作，但必须与 live Agent cap 分开命名，不能称为修改 Agent 后仍然是同一基线。

### 4.2 硬件不能当作可忽略的迁移因素

拟在 RTX PRO 6000 上开发，在 4×B200 上做正式实验；具体租赁实例尚未确定。开发机结果用于验证机制和脚本，不直接作为 B200 的效益数字或校准标签。B200 上重新完成 E0、容量/压力检查和需要的校准。

记录 GPU 型号/UUID、显存、功耗限制、驱动/CUDA/PyTorch/vLLM、P2P/NCCL 连通性、实测通信能力、CPU/RAM、机器与租赁 ID。同一 paired block 不跨机器。四卡也不用于同时运行多组相互争用通信资源的“独立实验”。

旧 A800 的 c=12/14/16 仅为历史 healthy/knee/stress，不能直接作为 B200 的相同工作点。若 16 个任务不足以压出 B200 的容量效应，应如实报告；扩大样本/map/concurrency 另建版本，不偷偷降低 KV 容量制造论文结果。人为限制 KV 可作容量敏感性实验，但单列，不能冒称默认硬件配置。

### 4.3 数据用途与分割

1. 现有前 16 条 SWE-bench Verified 和旧 trace 已经被反复观察，属于探索数据，不能再宣称完全未见。
2. 从这些 trace 选择实际 prompt/工具返回/生成长度用于微基准；工具内容长度按真实 token IDs 计，不只看 `assistant.content`。
3. 新的 state collector 先做有限自然轨迹采集，描述研究域。真实状态频率不能由手工挑选的微基准比例代替；记录采集时的路由策略，频率只代表该策略下的分布，不视为策略无关的环境常数。
4. 选参数、窗口和阈值只用开发集；最终保留独立运行块，并尽可能用此前未用于调参的完整 episode/task 作为测试集。额外 sample list/map 在正式实验前确认。
5. 同一 episode 的相邻 turns、同一初始状态的重复及近乎相同 prompt，不跨训练/测试泄漏。只按请求行随机拆分不够。

## 5. 测量口径与对照单位

### 5.1 决策前输入

记录 N/H/A、ready C_P/C_D、U_P/U_D、B_D/K_D、两端 Q_tok/Q_att、eligible/scheduled/blocked、pending、容量、窗口统计、snapshot 时间/epoch/覆盖。当前候选不计入背景积压；同一 physical work 不重复计数；未知为 null，不当冷缓存或零负载。

N 来自实际规范化后的完整 token 序列；H/A 只有前缀边界可证明时才填写。Probe 使用的 IDs 必须与实际请求一致；当前 API 的 `canonical_chat_verified=false` 不是已经完成这项证明。查询与执行之间的 C 变化要另报，不能因后续 miss 就反推探测一定错误。

线上特征只允许使用决策时刻之前的信息。当前实际 completion、下一次 cached tokens、最终 steps 和请求执行期间的最大负载属于事后标签。TTL 研究的未来 tool gap 也不能泄漏给可部署策略。

### 5.2 结果：保留原评分，但不把它当唯一成功标准

微基准先沿用等权 PPD score：

```text
S = (TTFT_Remote - TTFT_Local) / TTFT_Remote
  - (TPOT_Local - TPOT_Remote) / TPOT_Remote
```

该分数是相对指标的权衡，不是节省的总秒数。不宣布 TTFT 优先，不为制造 Remote 而改权重。实测接近零且波动覆盖零时，记录不确定，而不是强行宣布赢家。

评分群体沿用 `candidate_turn2_first_attempt_v1`：仅指定候选的逻辑 Turn 2、首 physical attempt、非 warmup；准备请求、P-only、背景和 retry 不混入均值。每请求先计算 TPOT，再作请求加权平均。状态准备成本不混进候选延迟，但纳入实验预算；完整策略运行中真实的历史计算不能作为 warmup 被删去。

| 层次 | 核心输出 | 解释边界 |
|---|---|---|
| 候选请求 | route-wide TTFT、request-mean TPOT、完整响应时间、G、失败/截断/重试 | P 的丢弃 token 不计 G；G≤1 时 TPOT 不成立 |
| 背景 decode | 固定 cohort、共同时间窗的输出数、ITL、最大 token age/停顿；窗口后恢复 | 无 token 不是零 ITL；不能让长 prefill 越过窗口就消失 |
| 服务运行 | 固定工作负载的完成时间、请求/生成吞吐、失败、preemption、实际重算与传输 | 不能把失败请求删掉后只比较成功者延迟 |
| Live Agent | 累计 LLM 等待、full-response/tool-ready、episode wall、工具间隔、退出原因、任务结果 | 原始 wall/质量差异可能伴随轨迹分叉 |

建议把**固定轨迹完成时间**作为后续 serving-policy 对照的主效益指标，并以失败、背景 decode 停顿和任务完整性作约束；这是待实验启动前确认的选择，不是修改已冻结的历史 score。没有预先定义 SLO 时不报告“goodput 提升”；若引入 SLO，先冻结阈值、统计群体和超时处理，并单独评价。

### 5.3 TTFT 和 TPOT 的可用性门槛

- 旧 `/v1/completions` 测量以客户端 POST 前到首个非空文本事件为 TTFT，以流完成时间计算 TPOT；保持 `legacy_client_stream_text_v1` 名称。
- Thinking/chat/tool 流若使用“首个生成 token，含 reasoning”，需单独验收并命名新 measurement basis；不能与首文本指标混池。
- D-only engine TTFT 不含先发生的 P 阶段，不能用于两路径端到端胜负。当前非流式 HTTP first byte 接近完整响应，也不是 TTFT。
- Node `queued_time` 仅到第一次 scheduled；`prefill_elapsed` 含分块间等待，不是纯 kernel 时间。额外等待修正不得重复计入。
- 同一个比较只使用同一 basis。未补好 route-wide 测量时，可以先做正确性、完整响应和背景停顿实验，但不能填造 score 表。

### 5.4 一个独立重复是什么

一个配对单位是“同一目标初始状态与背景脚本，分别重建后执行一次 Local 和一次 Remote”。每次重建都核验 prompt、缓存、B/K、积压和容量；实际状态不在预设容差内就记 `state_setup_failed`，不作为合法配对，失败次数和准备成本仍保留。

按机器、节点对、时间块、场景和内容种子分组，组内随机安排 LR/RL；建议冻结种子 `20261027`，生成并归档实际顺序。不能把所有 Local 跑完再跑 Remote。硬件/编译 warm-up 与候选 KV warm-up 分开，前一实验产生的缓存必须经过排空、重置或可验证恢复。

同一次共享 GPU run 的请求、token 和采样点不是独立重复。整套策略对照以完整 run/实验块为单位，按块汇总不确定性。三次重建只够探索方差，不保证统计功效。

### 5.5 Replay 的必要条件

Live Agent 用于观察真实工作量和最终生态验证；机制归因优先使用受控请求或 replay，两者不是互相替代。

**只回放 prompt 和固定 max_tokens，不能保证多轮 KV 轨迹相同。** 不同执行条件可能生成不同 token；下一轮若直接使用录制 prompt，服务器上一轮生成的 KV 就可能与该历史不匹配，从而制造假的 cache loss。

严格多轮计算 replay 需要固定规范化 prompt IDs、实际生成 IDs、生成步数和工具结果/间隔，并验证跨轮 token-LCP。若使用强制下一 token 的计算 replay，也必须每步真实执行模型 forward，验证其额外开销、模板/协议与模型路由行为，并与正常生成分开标注；不能拿预存响应直接返回而跳过 decode。

在该 harness 尚未完成时，先做独立候选状态的 E1–E3，再做有限 live；不宣称已有严格的全流程同工作量性能比较。Closed-loop replay 按上一响应完成后等待录制 tool gap 再发下一轮；open-loop 发压用于独立请求和到达突发实验。不得在同一 episode 前一轮未完成时强发下一轮，再称为正常 Agent 回放。

## 6. E0：先验证观测与测量，不急于验证算法

E0 是后续实验的入口，不是“新策略比旧策略快”的实验。

### 6.1 功能与状态验收

1. 验证当前 scheduler/并行布局处于 observer 支持域；不为迎合观察器而静默修改 baseline 的调度配置。
2. 对冷/热/部分前缀、尾 block、取消、抢占、cache reset、KV 接收未就绪分别核对 probe 与真实执行；查验 LRU、refcount、命中统计没有被查询修改。
3. 证明 chat token 对齐；完成 proxy→engine 的原生 request ID、accepted/terminal ACK 映射，核对 pending 去重。不能把 HTTP timeout 当作工作已结束。
4. 对混合 decode/prefill 的已知输入核验 B/K、E/S/T 和 Q；真实完成之前登记的 block 不能被当成 ready。
5. 验收 route-wide 计时及背景 token 事件；observer 私有 ready 元数据不自动等于完整 block eviction 事件流。
6. 当前 accepted/terminal 记录存在容量上限，长实验需可靠回收或明确分段；不能删除账目后继续声称完整覆盖。

### 6.2 开销对照

比较 observer 关闭、仅开启记账、低频 state-only、低频 state 加定向前缀探测四种配置。固定相同输入与运行块，分别报告 CPU/IPC/探测耗时以及真实吞吐、完整响应和背景 ITL 差异。探测频率只改变一项；不能把 10 Hz 限流上限当推荐设置。

门槛分开设定：语义测试要求没有已知的乐观假命中/重复计数；性能要求在预算内。建议先把吞吐或请求均值损失 2%、p95 损失 5% 作为**待确认的工程预算**，不是论文结论或统计显著性阈值；用实际波动判断能否分辨该量级。若开销已接近潜在路由收益，先降频/复用 hash 或缩小方案，不继续扩大校准。

## 7. 首批机制实验：E1、E2、E3

以下矩阵是低成本探索模板。`K` 指 1024 tokens；使用 tokenizer/block 对齐后的实际值。所有水平在看到路径优劣前根据容量和 trace 分布确认；不可因 Remote 没赢而不断换点。

### E1：同一 prompt，实际 KV 前缀是否改变最佳路径？

**对应 H1，也为 H0 提供第一批证据。**

- 请求长度 N：16K、64K 两档；逻辑 append A 暂取 512，H=N−A，模板前缀证据不成立时不伪造 H。
- 每端前缀：高复用约为 H，经 block/尾部规则修正；低复用为已证实的冷前缀。
- 组合：P高/D高、P低/D高、P高/D低、P低/D低，共 `2×4=8` 个状态。
- 背景：无其他可执行 prefill、无活跃 decode，保留足够 KV 余量，避免同时测试容量阻塞。
- 候选输出：先用同一独立微基准预算，例如 G=256；采集实际 G。它不是线上预测特征，不能作为 Agent 输出分布的替代。

通过合法 warmup/缓存压力操作产生并核验状态，不允许仅修改 hash 表来假装已存在有效 KV。背景空闲不等于两端缓存为空；隔离缓存状态操纵与活跃计算。若高/低组合不能在当前数据面可靠建立，记不可实现，不补造数据。

输出两路径 TTFT/TPOT/完整响应、实际复用和重算、实际传输。只有完成传输计量后才报告 NCCL bytes/time，不能把 P/D HTTP 时间当纯通信。

支持证据是缓存变化对两路径的**差异效应**：既可表现为胜负反转，也可先表现为显著扩大/缩小收益。若缓存影响很大但永远同一路径占优，只能支持“缓存影响性能”，尚不支持“缓存感知路由有用”。

### E2：相同请求与缓存，decode 背景是否改变路由价值？

**对应 H2、H5；不能只让背景请求存在，而不验证它们正在 decode。**

选两种候选请求，例如固定 N=64K、C_P≈32K，分别令 U_D≈512 和 U_D≈8K。背景 prefill 先排空，使 Q_P/Q_D≈0，保持待测缓存状态。

每种候选配下列五种 decode 背景，共 `2×5=10` 个状态：

| 背景 | B_D | 单序列 ready context 约值 | K_D 约值 |
|---|---:|---:|---:|
| 无 decode | 0 | 不适用 | 0 |
| 少量短序列 | 2 | 8K | 16K |
| 少量长序列 | 2 | 32K | 64K |
| 较多短序列 | 8 | 8K | 64K |
| 较多长序列 | 8 | 32K | 256K |

“少量长”与“较多短”提供相近 K、不同 B 的对照；同 B 的短/长背景检查 K 的价值。最后一档若超出实机容量，统一缩放水平并重写 manifest；不得把 OOM 样本冒充高 decode 计算压力。

背景请求在候选进入前完成自身 prefill；冻结它们的内容、剩余生成工作量与后续到达脚本。两路径允许背景随执行自然演化，不能为了维持相同 B 而事后使用不同补流策略。测量当前 B/K 和实际 scheduled batch，而不是只使用目标配置。

对背景干扰，先冻结共同观察窗，再比较同一 cohort 的产出和 token age；窗口太短的情况保留并继续观察恢复。增加少量相同背景但不插入候选的参考运行，有助于分清既有波动与新增干扰。背景损失不自动加入原 score，先作为 H5 证据。

若需要验证“同一 B/K 是否足够”，只在后续留出集补均匀长度与长短混合长度对照，不立刻把完整长度分布增加成一条全量校准轴。

### E3：积压会否改变胜负，哪种简化信号更有用？

**对应 H3，同时检验 AMPD-style 队列求和在当前执行引擎上的适用性。**

从 E2 预先选两种候选状态，不只挑已经观察到反转的点；为各自构造四类背景：无额外 prefill、仅 P 有、仅 D 有、两边都有，共 `2×4=8` 个状态。目标剩余工作量可先取 16K，准确值、组成和进度以快照为准，B/K 保持在预定范围。

两个注意点：

- 这里增加的是**候选之前已有的背景工作**，不把候选自身 U 加进 Q；两路径分别重建同一背景。
- 有无积压之外，后续补“同 Q_tok、一条长任务/多条短任务”和“同 Q_tok、不同已完成历史 E”的挑战场景，检查简单标量隐藏了多少信息。请求数、Q_tok 和 Q_att 不是等价量。

在相同已采集数据上比较以下信号，不为每个信号重跑全套 GPU 实验：

| 信号 | 含义 | 主要风险 |
|---|---|---|
| 原 lifetime QPS、窗口请求到达率 | 过去来了多少请求 | 单位/时间口径不匹配，无法表示已处理多少 |
| 窗口到达的未命中 token 速率 | 过去送入多少初始计算工作 | 输入速度不等于当前存量，抢占重算需另记 |
| 当前/窗口平均未完成 prefill 请求数 | 积压几条 | 忽略每条大小 |
| 当前 Q_tok、窗口平均 Q_tok、EWMA | 积压多少待计算 token | 忽略部分历史与调度差异，窗口会滞后 |
| Q_tok+Q_att | 更多计算结构 | 状态与校准成本更高，未必带来增量收益 |
| 近期 TTFT/ITL、排队时长 | 已执行请求的表现 | 内容混杂、滞后、未完成慢请求尚未贡献样本 |

P、D 分别统计，不只用总和或差值。固定周期采样按实际时间间隔计算窗口平均，不按请求到来次数平均；覆盖不足标未知。初始窗口候选可用 1/5/10 秒，在开发集挑选后冻结；突发和排空过程留作验证，不能用未来结果挑每个请求的最佳窗口。

窗口挑战采用预先安排的均匀到达、同窗口数量的突发、停止到达后的排空等轨迹；使用相同请求大小集合，并固定候选注入时刻。测试“相同窗口 QPS 不同积压”与“相同窗口积压不同瞬时状态”，而不是只画全程相关系数。

AMPD-inspired 成本对照先用独立 profiling 的 f(h,a) 对已知 prefill 逐项求和，再与实测排队及路径排序比较。正在执行的剩余时间、合批/分块、重排和 blocked 要分别说明。报告 bias/绝对误差、尾部误差和路径排序错误；低平均误差不保证决策边界正确，高误差也不必然导致选错。本机误差不归因于未经复现的 AMPD 原系统。

在当前单向数据面上，若按 f 建本机对照，应以节点实际 ready 前缀与缺失后缀为输入，而不是假设 P 能从 D 取回全部历史后只算 A。串行队列求和、使用剩余进度后的求和、低维经验修正分别命名；不得把适配后的差异解释为 AMPD 原公式已经包含这些能力。

## 8. 次级诊断：E4 特征与目标，E5 TTL

### E4：确认旧代理误差是否真的造成可改进的损失

先在 CPU/已记录 trace 上统计：N、可证明的 H/A、实际 G（含 reasoning/tool call）、tool observation tokens、requested cap、旧分类和真实测量来源。分别看 tool 类型、有效/无效工具调用与 episode，而不是用所有请求的一个中位数概括 Agent。

旧 output 值有误、append 比可见 response 长，仅能说明代理变量不理想；还需将样本放到 E1–E3 的配对结果中，检查是否导致了错误动作。旧表全 Local 时，修改特征但不改变动作的 shadow 结果不能作为性能改善证据。

在少量固定状态上增加短/长 G 对照（例如 128/2048，固定输入与背景），检查移除 output 后的动作是否对生成时长分布敏感。离线实际 G 可以用于事后诊断或 oracle 参考，不能泄漏给可部署路由。若优劣对 G 强烈敏感，应报告方法适用域，而不是宣称已完全解决未知输出。

同时检查相同 N/U 下不同 H/A 的影响，以及短逻辑 append、低 D 复用的 bypass 反例。该反例需另选 A<512（例如 128）的候选，E1 的 A=512 不能直接覆盖 `<512` 的 bypass 分支。所谓“输入修复收益”与“增加状态信息收益”分开：已修复的 tokenizer、loader、tool schema 不重新记为新算法贡献。

H5 的结果在这里汇总：列出 score 与完整响应、背景停顿相冲突的样本。只有冲突有足够规模，才进一步讨论 SLO 约束/惩罚；SLO 惩罚改变目标，不能和保持原权重的输入消融混为一项。

### E5：先确定有多少 cache loss 是 TTL 能解决的

先只记录证据，不启用 pin。对每个相邻请求 transition 分类：

1. 模板/reasoning/tool 序列变化导致 token-LCP 提前结束；
2. 可复用前缀的 block 确实被回收，下一次使用需要重算；
3. offload/restore 或远端接收；若当前未启用则写明，不由 miss 猜测存在；
4. 尾 block/末 token 的合法重算；
5. epoch、节点、retry 或证据缺失导致的未知。

只有第二类及其后续真实代价直接支持 TTL 的容量收益假设。统计工具返回 gap、所需保护的唯一物理 bytes×时间、跨 episode 的共享块和被挤占工作；不把重复事件的 lost tokens 当作唯一驻留容量。

先报告可避免失效的频率和受影响时间分布。把所有 miss 假设为免费命中只能作非可实现的诊断参照，不能当作等容量 TTL 的真实上界；把单请求节省时间直接求和也不等于整个 run 的 wall time 节省。

确认有空间后，才单独申请实现有界保护，做“固定路由/新路由 × TTL off/on”的 2×2 对照。相同显存容量、KV预算、输入工作和并发，显式限制 pin 占用并清理取消/结束/过期租约；到期解除保护，不强制驱逐。首先测试固定 TTL，再考虑工具 gap/路径感知；公开代码中的简化 pin 不冒称 Continuum 完整算法。队列优先级、offload 与 TTL 若一起变更就无法分离贡献。

## 9. 改进空间怎样量化

本轮至少产出三类数字，不能只报告“Remote 赢了几个点”。

### 9.1 状态内的效应与不确定性

每个有效状态报告两路径 TTFT、TPOT、完整响应、背景停顿、失败和差值，保存独立重复。区分 Local 优势、Remote 优势、实际接近、证据不足和路径不可用；失败不是零延迟，也不能以 retry 成功覆盖首 attempt 失败。

分析以配对差值和跨独立运行块的不确定性为主。样本充足时可按整个 paired block 重采样估计区间，保留节点/机器分组；不重采样单个 token 来夸大样本量。三次探索重复先展示全部点、范围和方向一致性，不把窄的伪置信区间或高阶回归系数当作确认性证据。多项假设的正式检验需预定主要对比与多重比较处理。

建议以 5% 的完整响应差、或原 score 的 0.05 差作为**探索性的最小实际效应候选**，正式确认前分别冻结；这两个量不是同一目标，更不是 p 值。小于阈值但高频的累积影响可以另报，不能事后随意换阈值宣布成功。

### 9.2 真实出现频率与局部可改进参照

用独立自然轨迹估计状态频率 p_s，并报告覆盖率。对某一明确指标 J，可计算：

```text
局部理想参照：Σ p_s · min(μ_Local,s, μ_Remote,s)
固定路径参照：min(Σ p_s · μ_Local,s, Σ p_s · μ_Remote,s)
两者差值：在这些已测状态与固定分布下，逐状态选择可能具有的空间
```

J 可以是完整响应时间，但不能直接把多目标 score 当作秒数。有限样本取最小值有乐观偏差：用一组独立重复选择动作，另一组评价，或明确把结果标为未校正的探索参照。未覆盖/失败状态另列，不能只报告对自己有利的覆盖子集。

这个参照**不是整套策略的可实现全局上界**：改变路由会改变后续缓存、积压和到达时刻，状态分布本身也会变。它用于决定是否值得开发，最终收益由 E6 验证。

### 9.3 特征的增量价值

在相同测量预算、相同训练/留出分割下，比较旧特征、加入 C/U、加入 B/K、再加入不同压力信号的简单决策模型。报告未覆盖率、动作错误及其代价、排序误差和观测总开销，而不只报告标签准确率。

既比较累计加入，也比较从候选完整模型中删除某一组的消融，以免单一加入顺序掩盖交互。只做预先列出的少数组合，不穷举所有特征子集并挑最好结果。新特征若没有降低独立测试的决策损失，就不因“看起来物理意义更好”而保留。

## 10. E6：证据足够后才实现并比较策略

根据 E1–E4 的结果，从以下候选中选择少量，不默认全部实现：

| 方法 | 作用与约束 |
|---|---|
| Static Local / Static Remote | 同硬件的两端参照；Turn 1 保持正常协议 |
| 原 PPD Dynamic | 原特征、原 score、原 bypass；目标硬件重新校准实际使用范围，缺测明确回退 |
| KV-aware empirical table | 仅加入实际复用，检验 H1 的独立价值 |
| KV+decode empirical table | 再加入 B/K，检验 H2；保留原评分 |
| 低维压力查表或独立拥塞修正 | 根据 H3 选择其中一种；相对校准参考背景修正，不能双算等待 |
| AMPD-inspired feedback/cost | 保持本机数据面并明确适配项；阈值、队列模型独立校准，不冒称原 AMPD |

不能拿 A800 上的旧表对比 B200 上充分调好的新表，然后把所有收益归因于输入。若无法在 B200 为原方法取得匹配校准，保留该对照作迁移诊断，同时以同机 Static 两端和等预算的经验基线为主要参照。

执行顺序为：独立状态留出验证 → 小规模计算 replay → 整套 closed-loop replay → 有限 live Agent。Shadow 只能验证实际执行路径的结果和覆盖，不能证明另一条未执行路径的反事实。

在完整 replay 中，固定总工作、工具 gap 和并发上限；策略之间比较整个 run，不能把单次运行内几百个请求当几百次独立实验。Live 保持 Agent 合同不变，单独报告轨迹长度、生成 tokens、工具行为与 resolved；不同轨迹的性能差不能仅靠简单除以 token 数消除。

## 11. 预算、停止规则与研究决策

### 11.1 首批不跑高维全矩阵

| 批次 | 不重复计算的目标状态数 | 两路径×初始3次独立重复 | 目的 |
|---|---:|---:|---|
| E1 | 8 | 48 次分支执行 | 实际前缀的效应 |
| E2 | 10 | 60 次分支执行 | decode 背景与外部影响 |
| E3 基础 | 8 | 48 次分支执行 | 积压的方向性效应 |
| 合计 | 最多 26 | 最多 156 次分支执行 | 决定哪些假设值得继续 |

完全相同的场景可以共用数据，但同一条记录不能算作两个独立重复。E0、无候选背景参考、窗口挑战、G 敏感性、留出确认、完整 replay 和 TTL 不含在 156 次内，分别申请预算。

先从上述矩阵取 4 个预先指定的极端/中间状态，各做两次配对，即 16 次分支执行，验证重建成本与波动；协议不变时可作为探索批次的一部分。该 pilot 不足以建立完整表或宣布显著收益。

预算按全流程算：

```text
总时间 = 启动与编译 + Σ(缓存/背景准备 + 状态核验 + 候选执行 + 排空恢复)
         + 状态准备失败与服务失败的实际耗时 + 留出/参考实验
```

若每次分支完整耗时为 1/3/5 分钟，156 次分别约为 2.6/7.8/13 小时；这是算术情景，不是机器实测工期。四卡卡时是机器墙钟的四倍。实际报价、存储/流量、Modal 和重复运行另计；B200 更快也不会自动缩短工具等待。

### 11.2 预先约定的停止与扩展条件

- **E0 不通过：**暂停算法校准，先修观测/计时。不能用错误状态证明算法有缺陷。
- **状态无法稳定重建：**缩小支持域或改 runner，保留失败记录；不把 setup failure 当某条路线输。
- **两路径在代表域内几乎总是同一方占优：**先确认长 context、真实常见的 G 与负载范围已覆盖，不能仅凭 G=256 的小矩阵宣布没有空间；确认后停止扩大路由表，报告适用范围，优先考虑该固定策略的容量/调度问题，不改 P:D 或权重追求 Remote 占比。
- **仅合成极端有收益：**扩大真实频率证据或缩小研究主张，不立即投入完整系统。
- **观测成本接近收益：**简化观测；更丰富特征本身不算成果。
- **低维积压信号不稳定：**检查遗漏因素与窗口滞后；只在有证据的区域补信息，不把所有字段乘成大表。
- **TTL 无可避免容量失效或净代价为负：**暂缓 TTL，不以 retention 上升代替端到端收益。

探索阶段允许按上述规则停止，但不能反复看 p 值、在第一次显著时停下。正式确认的样本量、检查时点和分析方法在 pilot 方差估计后另行冻结；留出数据不用于重调窗口/阈值。若证据不足，应报告“不确定”，不当作证伪或等效。

## 12. 产物、实施缺口与下一步

### 12.1 每次实验应归档

| 产物 | 必需内容 |
|---|---|
| run manifest | 代码/模型/模板指纹、硬件、配置、map、内容与随机种子、生成/工具 gap 模式、采样率、计时 basis、预算、超时与判废规则 |
| scenario 与 run order | 目标/实际状态、节点对、配对 ID、独立重复、LR/RL 顺序、准备操作和失败原因 |
| 决策前状态 | 原始快照、各字段来源/时间、有效覆盖、pending 与实际请求关联 |
| request/token/cache events | 两路径完整结果、背景事件、失败/重试、真实 prefix/eviction/transfer 证据，缺失明确标注 |
| summary | 每状态两路径差值、波动、频率/覆盖、背景影响、错选代价、总预算消耗；不只存推荐动作 |

报告图表优先为：路径收益随实际复用/decode 背景的变化、queue 信号对相同 QPS 状态的区分、候选指标与背景停顿的冲突、自然流量覆盖和按频率加权的局部空间。未知值和失败单独展示，不绘成零。

### 12.2 尚未具备、不能假装已经可运行的能力

- 原生 observer/IPC/NCCL 验收、canonical chat IDs 与 proxy pending 对账；
- 两路径可比的 route-wide 首 token 测量，以及背景 cohort 的细粒度停顿记录；
- 可重建缓存和背景的配对 runner、运行顺序/状态容差验收；
- 完整 token 级计算 replay 和 block 失效归因；
- 新策略、AMPD-inspired 对照和 TTL 的实现。

本文不提供不存在的“一键实验命令”，也不因已有 138 项 CPU 测试而跳过以上条件。

### 12.3 开始前需确认的最小清单

1. 目标机器及 4 卡拓扑、版本与配置；不混用 RTX/B200 校准。
2. E0 的测量 basis、状态容差、开销预算和探测频率。
3. E1–E3 的可实现水平、候选/背景生成长度及总 GPU 小时上限。
4. 状态/episode 分割、随机运行顺序与独立确认预算。
5. 最小实际效应、失败/背景损害的约束；若使用 SLO，另定具体阈值。

**下一步只进入 E0 和 16 次分支的可行性 pilot，不直接启动新的高维 calibration。** 若首批证据不支持路由改进，就保留负结果并调整研究方向。详细实测结果追加到 experiment log；handoff 更新完成状态，不能把本文的预期写成结果。
